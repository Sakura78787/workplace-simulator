# 架构与业务决策日志 (Decision Log)

本文件用于记录项目推进过程中的关键业务砍档、技术妥协及架构决策，解释“为什么我们选择这样做”。

---

## 2026-04-20 进度冲刺与 MVP 边界定调

在完成 Task 11 后，产品与执行方针对 `roadmap_to_100_percent.md` 的疑点进行了最终决策，确立了**“极简落地、控制成本、快速验证”**的原则。以下为关键决定：

1. **废弃 iOS 专项适配 (Task 15)**
   - **决定内容**：本期 MVP 明确不解决 iOS Safari / 微信环境下的 `html2canvas` 导出异常、橡皮筋回弹和键盘遮挡问题。全量保 Android 及 X5 内核。
   - **Why**：iOS 的前端渲染坑点极多，修补性价比极低。不让技术债卡住产品整体验收。

2. **砍掉账户与登录系统，采用匿名同步 (Task 13/14)**
   - **决定内容**：不接入微信静默授权，不用手机验证码。
   - **Why**：降低用户的进入门槛，提高裂变转化率。
   - **How to apply**：使用本地生成的 UUID 追踪。A/B 测试仅记录转化点击（建表 `ab_clicks`）；图鉴上报采用纯静默元数据同步（建表 `pokedex_sync`）。榜单只需展示脱敏后的匿名玩家代号。

3. **零新增环境的新职业拓展 (Task 16)**
   - **决定内容**：未来新增研发(RD)与测试(QA)等岗位时，绝对不改底层机制，不新增任何独立或特殊关卡环境。
   - **Why**：降低代码变动风险与心智成本。所有职业均能套入这套底层情绪框架。
   - **How to apply**：强制沿用“热身->甩锅->插单->死线->背锅”这 5 大主线流程，只在 `game-data.json` 里做纯文本换皮。

4. **极简裂变，不搞空降逻辑 (Task 17)**
   - **决定内容**：扫别人分享的海报二维码后，新用户统一直达项目首页。
   - **Why**：复原他人的“死亡现场”涉及复杂状态透传与恢复，且极有可能暴露合规边界或卡死流程。
   - **How to apply**：不做复杂的 deep link 参数解析，直接拉新。

## 2026-04-20 A/B 测试建表与埋点防抖约束 (Task 13)

针对分享按钮的 A/B 实验埋点，为了极速上线，做出以下轻量化技术约束：

1. **表结构与直连**：建表 `ab_clicks`，包含 `id`, `device_id`, `variant`, `event_name`, `created_at`。允许前端使用 `anon key` **直连写库**。
2. **安全与防刷**：开启 RLS，仅放行 `INSERT`，**全面封禁 `anon` 的查询和修改权限**以防拖库。前端必须加防抖（~1000ms），不刻意做基于后端的防重 UPSERT。
3. **分配机制**：以持久化在 Zustand 中的 `deviceId` 做简单的本地散列或奇偶校验，来固化映射可读枚举 `self_mock` (A组) 或 `pk_taunt` (B组)，绝不动用中心化配置下发。

## 2026-04-20 PRD 收官执行决议 (Task 16/17)

在 Task 14 验收通过后，进入 PRD 收官阶段，明确以下实施决议并已落地：

1. **剧情真源强收口**
   - **决定内容**：运行时剧情节点不再读取本地 mock，统一以 `memory-bank/game-data.json` 为唯一真源。
   - **Why**：避免“文档与运行时数据分叉”，降低后续扩角色返工。
   - **How to apply**：`src/config/storyNodes.ts` 改为读取并规范化 `game-data.json`，提供最小容错。

2. **Task 16 采用“零新增机制”扩角色**
   - **决定内容**：新增 RD/QA 仅做文案与选项换皮，复用原有 3 指标 + 5 阶段主流程，不增新系统。
   - **Why**：满足增长面扩容同时保持玩法稳定与维护成本可控。
   - **How to apply**：在 `game-data.json` 扩节点、`LandingView` 增入口、`RoleType` 与 LLM 上下文扩展到四角色。

3. **Task 17 严格首页引流**
   - **决定内容**：分享二维码固定跳首页，不允许任何快照恢复/状态透传。
   - **Why**：规避合规与状态一致性风险，确保裂变链路简单可控。
   - **How to apply**：结果页二维码常量固定 `#/`，全仓清理并禁止 `snapshotId` 解析入口。

## 2026-04-20 发布门禁收口决议（PRD §7）

1. **门禁标准不降级**
   - **决定内容**：代码完成不等于上线完成，必须以 Android Chrome + 微信 X5 真机录屏证据作为最终发布门禁。
   - **Why**：PRD §7 的核心风险在真实终端行为（键盘、长按保存、慢网兜底），仅靠本地构建无法替代。
   - **How to apply**：在 `implementation-plan.md` 维护 8 项验收记录与证据链接，未签字前状态固定为“待验收”。

2. **隐藏结局可观测闭环**
   - **决定内容**：自由输入触发隐藏结局后，必须在结算页与图鉴展示标签和语境摘要。
   - **Why**：避免“有触发、无呈现”的黑箱体验，确保 PRD 对隐藏结局展示要求可核验。
   - **How to apply**：前后端协议扩展 `hiddenEndingTag/hiddenContext`，并在本地 `historyPokedex` 持久化。
